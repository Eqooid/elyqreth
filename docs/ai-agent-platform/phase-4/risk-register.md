# Phase 4 final risk register

Reviewed 2026-10-27, Asia/Bangkok. The [acceptance decision](acceptance.md) is limited to the approved, trusted, loopback development/test deployment. Production and multi-tenant release are not accepted. Severity below is retained; a condition excluded by the approved scope is not silently described as a resolved vulnerability.

| ID | Risk / severity / impact | Existing mitigation and evidence | Follow-up | Blocking classification |
| --- | --- | --- | --- | --- |
| P4-R01 | **HIGH if publicly exposed:** fixed-owner local capabilities are not human/tenant authentication. Public access could disclose/control an owner's Agent resources. | Default-deny startup and bind/peer/Host/Origin restrictions; separate operator/read/interaction audiences, exact route allow-list, owner/Agent/binding checks and transactional revalidation. Actual foreign-owner HTTP denial, production/default denial and credential-rotation tests pass. | Design production identity, tenancy, delegation/revocation and deployment security before broader access. | **Blocks public/multi-tenant release.** Not an unresolved authorization bypass in the approved local deployment; local acceptance does not permit exposure. |
| P4-R02 | **MEDIUM:** a hard-crashed native attempt can remain persisted RUNNING with UNKNOWN liveness. No automatic recovery worker resumes or repairs it. | Real child-process kill/restart, 20-second lease observation, zero result/terminal fabrication and rejected repeat Start verified in T09/T10. Native quarantine remains authoritative. | Specify authoritative crash reconciliation, external side-effect idempotency and operator recovery before detached/distributed execution. | Non-blocking for documented local observation semantics; blocks claims of autonomous crash resumption. |
| P4-R03 | **MEDIUM:** synchronous HTTP execution/navigation and cooperative cancellation cannot guarantee remote provider termination or billing. | Separate action-pending vs lifecycle status, explicit cancellation confirmation, both versions, actual cancellation/completion/lost-response/reload tests. No mutation retry. | Review durable asynchronous execution/cancellation semantics if required by a later architecture task. | Non-blocking under P4-ADR-002/005; blocks detached-work/instant-cancel guarantees. |
| P4-R04 | **MEDIUM:** no server per-caller Task quota/rate limiter; a compromised authorized local capability can create excess saved Tasks. | Trusted loopback boundary, bounded bodies/pages/results, coordinator capacity, native per-Agent fencing and controlled client retries. | P4-R05 | **MEDIUM:** pattern-based credential rejection and output escaping are not general DLP or prompt-injection prevention. The stronger automated pinning suggested by the T01 plan is not claimed as implemented. |
| P4-R09 | **LOW:** live paid providers were not run in final acceptance. Provider availability and external behavior are deployment-specific. | Primary E2E uses genuine deterministic rule-based execution. Existing provider/LLM/tool unit and PostgreSQL regression coverage passes; Phase 2 historical live evidence is preserved separately. | Run existing authorized opt-in live checks when enabling a real reviewed profile; never require paid credentials for primary acceptance. | Non-blocking for rule-based primary workflow; no fresh live-provider compatibility claim. |

No unresolved Critical or High authorization/correctness defect remains within the approved local scope after the executed acceptance checks. Scope exclusions above do not grant exceptions to backend authorization, identity isolation, mutation idempotency or mandatory native E2E verification.
